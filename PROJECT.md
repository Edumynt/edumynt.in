# Edumynt Project Guide for AI Assistants

This document provides a comprehensive overview of the Edumynt project, its structure, conventions, and goals. Please read this guide carefully before making any changes to the codebase.

## 1. Project Overview

**Edumynt** is a static, client-side educational platform designed for English literature students. It provides structured courses, lessons, and learning materials in a web-based format that also functions as a Progressive Web App (PWA).

- **Purpose**: To deliver high-quality, organized literary course content.
- **Architecture**: Static site generated by Astro. All user-specific data (e.g., progress, bookmarks) is stored client-side in the browser's `localStorage`. **There is no backend database or server-side logic.**
- **Content Source**: The content is primarily managed in Markdown (`.md`) and MDX (`.mdx`) files, designed to be compatible with content exported from an Obsidian vault.

## 2. Technology Stack

- **Framework**: [Astro](https://astro.build/)
- **UI**: [Tailwind CSS](https://tailwindcss.com/)
- **Content**: [MDX](https://mdxjs.com/) (for embedding components in Markdown)
- **PWA**: [VitePWA](https://vite-pwa-org.netlify.app/)
- **Package Manager**: npm

- **The most important directory is `src/content/courses/`. This is where all educational content lives.**

## 4. Content Management

This is the most critical part of the project. All content is managed through files in `src/content/courses/`.

### 4.1. Course Structure

- Each direct sub-directory inside `src/content/courses/` represents a single course. The folder name is used as the course's unique identifier (slug).
- **Unlimited Nesting**: Courses can have an unlimited depth of nested folders to organize content into chapters, sections, and sub-sections.
- The URL structure of a lesson is directly derived from its file path.
  - `src/content/courses/my-course/chapter1/lesson-one.md` → `/courses/my-course/chapter1/lesson-one`

### 4.2. Frontmatter (Required for all content files)

Every `.md` or `.mdx` file inside a course directory **must** contain YAML frontmatter.

**Example:**
```yaml
---
title: "Your Lesson Title"
description: "A brief description of the lesson for SEO and previews."
course: "Course Name"          # CRITICAL: Must EXACTLY match the course's root folder name.
order: 1                       # Optional: An integer to sort lessons within the same folder.
tags: ["tag1", "tag2"]         # Optional: Tags for filtering and organization.
draft: false                   # Optional: Set to true to hide a lesson from the production build.
date: 2024-01-15               # Optional: The creation date of the lesson.
---
```

**Key Rules:**
1.  **`title` is required** and is used for navigation and display.
2.  **`course` is required** and **must** match the name of the top-level folder for that course (e.g., if the file is in `src/content/courses/indian-writers/...`, the `course` value must be `"Indian Writers"` or whatever the designated course name is). Check existing files for the exact name.
3.  The `chapter` field is **deprecated**. The file system hierarchy replaces it.

### 4.3. Creating New Content

1.  **To add a new course**: Create a new folder inside `src/content/courses/`.
2.  **To add a new lesson**: Create a new `.md` or `.mdx` file within the appropriate course folder (or sub-folder).
3.  **File Naming**: Use `kebab-case` for all file and folder names (e.g., `my-new-lesson.md`).
4.  **Add Frontmatter**: Ensure the new file has the correct and complete frontmatter.

### 4.4. Course-Specific Instructions

Some courses may have unique formatting rules. For example, the "Literary Terms By MH Abraham" course requires specific HTML for Hindi translations. Always check for a relevant guide (like `LITERARY-TERMS-FORMATTING-INSTRUCTIONS.md`) or examine existing files in the course before adding new content.

## 5. Development Setup

All commands are run from the project root.

1.  **Install dependencies:**
    ```bash
    npm install
    ```
2.  **Start the local development server:**
    ```bash
    npm run dev
    ```
    The site will be available at `http://localhost:4321`.

3.  **Build for production:**
    ```bash
    npm run build
    ```

## 6. Key Conventions

- **File Naming**: All files and folders, especially within `src/content/`, should use `kebab-case`.
- **Static First**: All new features should be implemented to work on a static site, primarily using client-side JavaScript and browser APIs (`localStorage`).
- **Check Existing Guides**: Before undertaking a task, check for relevant `.md` guides in the root directory. They contain critical information.
- **Frontmatter is Law**: The site's navigation and structure are built from frontmatter. Incorrect or missing frontmatter is the most common cause of bugs.

## 7. Project Roadmap Summary

The project has a clear vision for future enhancements, as outlined in `UX_IMPROVEMENTS_ROADMAP.md`. The goal is to enrich the user experience while maintaining the static architecture.

**Key planned features include:**
- **Analytics Dashboard**: Visualizing user progress.
- **Smart Bookmarking**: Saving and organizing content.
- **Reading Timers**: Estimating reading time for lessons.
- **Keyboard Navigation**: Power-user shortcuts.
- **Text-to-Speech**: For audio-based learning.

When implementing new features, consider if they align with this roadmap.
